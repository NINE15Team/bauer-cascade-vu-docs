VU concepts

Engine VU main.js
VU Custom's Front-End Customizer bundle, loaded from their S3. Owns the 3D scene, option sets, recipe state, variant mapping, and the actual cart POST. Not in our repo, not modifiable, minified. Bauer and Cascade load it from different hosts.
Product slug section setting product
VU's product-line identifier: vapor, supreme, bauer-flylite, Pulse_ti_3mm, supreme-fuse. Not a Shopify handle. Case-sensitive — passed through as typed.
Data variant data_variant
VU's 3D model identifier: bauer-shadow, steel-b2c, xrs-pro. Also not a Shopify handle. Downcased in Liquid before it reaches the tag. VU issues it; without one there is no customizer.
Recipe · Recipe ID
The current selection state, held by the engine and readable at customizer.recipe. VU define a Recipe ID as “a unique eight-character token generated by VU Custom that captures all of the user selections and customization/personalization within the customizer” — that is the token in ?recipe_id=, which auto-opens the modal with those selections applied.
Template VU sense — not a Shopify template
VU's configuration for one product: the 3D model or photography, the selectable options, and the business logic. Lives in VU Admin. Name collision: in our docs “product template” normally means the Shopify Theme Editor template. When VU say template, they mean this.
Tabs
VU's term for the sections within a template that group elements — the steps a shopper walks through in the modal. vu_main.js styles and wires their navigation; which tabs exist is VU-side configuration.
Zones
Areas of the product where customization can be applied. This is what recipe.color_zones refers to: the codes in a section's custom-colour list are zone colour codes, and a match triggers the longer lead time.
Starting Points
A native VU feature — a template previewed with customization pre-applied, to drop a shopper into the customizer with selections already set. Overlaps with the restore-selections POC, which does this by hand. Worth raising with VU before investing further in the POC.
Perspectives
The camera views configured per template — the angles a shopper can rotate through.
Travelers
VU-generated production document carrying order info, recipe info, perspectives and print-ready artwork links. Entirely downstream of the theme, but it is what the factory works from.
Upcharges
VU's mechanism for charging more for particular selections. Not used by our Bauer pricing, which is Shopify-side. If pricing ever needs to vary by option, this is the VU feature to ask about rather than building it in the theme.
Profanity Filter
VU Admin setting governing what shoppers may type into personalization fields — relevant to the name and number on a skate tongue. Configured by VU, not in the theme.
Element
VU: “defined classes of functionality that power selections/interaction with presented options in the customizer.” In practice, one configurable field in the recipe, keyed by code — color, size_left, fit, tongue_model. Exposed as customizer.elements[code] with .value ({name, code}) and .setValue(). See Restore for the gotchas.
vu_engine
Sentry tag recording which engine build loaded: production, staging, qa or development. Sourced from settings.vu_customizer_environment. Not the Sentry environment.
Key VU events
customizer.scene-rendered — 3D ready; we open the modal and compute the lead time here. customizer.recipe-updates-complete — selection changed; drives the custom-colour lead-time swap. customizer.add-to-cart-fail — cart POST failed.

Theme-side concepts

The shell
Everything Nine15 built around the engine: trigger, modal, tabs, focus trap, price, guides, lead time, cart line attributes, Klaviyo share, Sentry. Bauer: section + snippet + vu_main.js/.css. Cascade: one snippet.
customizerLineAttributes
Global array written on scene-rendered, holding the estimated delivery date and the SAP fields. VU's cart library reads it and attaches the values on add-to-cart. This is the entire theme-to-engine cart handshake.
Lead time
Build days, resolved as: product estimated_delivery metafield → else blade setting if product.type == 'MyBauer-Steel' → else skate setting. Rendered as a weekdays-only MM/DD/YYYY date.
Custom colour lead time
Longer lead time applied when the shopper's color_zones code appears in the section's comma-separated list. Recomputed live on recipe updates. The list is empty on every live CA product.
Hide price B2B path
Section setting. Suppresses price and swaps add-to-cart for “Send to Retailer”. Off on all live CA products.
showmodal
The attribute value vu_main.js binds to. Any element with name="showmodal" opens the modal. The rich-text “VU Customizer Trigger” block sets it from its Attribute field.
SAP cart keys
_Custom Product Category, _Customization Level, _CustomerRequestDate, _LeadTime. Underscore-prefixed so Shopify hides them from the storefront line item. Spelling is an SAP contract — do not rename.

Parties and systems

VU Custom the vendor
The customizer vendor — vucustom.com. Owns the engine, the 3D assets, the option sets and the recipe API. Reachable via the shared Slack channel #bauer-vu-nine15. Their own documentation: vu-custom.gitbook.io.
VU OS the platform
VU Custom's platform as a whole, in three modules: the Front-End Customizer (what shoppers use), VU Admin (template and asset configuration), and VU OMS (orders, factories, fulfilment). The s3.amazonaws.com/vu-os host in our dependency list belongs to this.
JTB
VU Custom's predecessor name, still throughout Cascade's code and hosts — jtb-snippet.liquid, silhouette3.jtbcustom.com. Same vendor, older naming. VU's public docs still show a jtbcustom.com embed pattern.
Spectrum
The previous customizer vendor, still live for Bauer sticks and goalie gear. Anything referencing cdn.spectrumcustomizer.com or a hashed custom_*_host setting is Spectrum, not VU, and not maintained here.
SAP
Bauer's ERP. Receives the cart line attributes and drives manufacturing. Wrong keys mean a technically successful order that reaches production with bad data.
DIG
The internal programme the restore-selections POC was requested under. Contact: James.

Easily confused

Sentry environment vs vu_engine
environment = shopper exposure, derived from shop domain + theme role (production / production-draft / staging). vu_engine = which engine build loaded, from theme settings. They are independent and often legitimately differ. Alert on the first, never the second.
Goalie steel vs goalie gear
Goalie steel (Pulse Ti, LS 5G, goalie-steel-b2c) shipped and is live. Goalie gear (pads, blockers, catchers) was started in 2025, never finished, and still runs on Spectrum.
mybauer-* vs bauer-* handles
mybauer-fly-ti-runner is the customizer product. bauer-fly-ti-runner is the stock retail SKU with no VU script. Easy to grab the wrong one in admin search.
VU Customizer section vs vu_customizer block
The section is the working path. The legacy block in main-product.liquid renders the snippet with no product, variant or main_source and produces a dead shell. See Bauer.
