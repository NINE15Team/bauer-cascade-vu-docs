Cascade

Helmet customizer on Cascade Maverik. Shell is jtb-snippet.liquid (3,226 lines), not Bauer's section/snippet split. Admin + live HTML, 26 August 2026.

An engine migration in progress

VU asked us to move to a new engine URL. Rather than cut every helmet over at once, we added a per-product override so old and new engine versions can run in parallel: Z and SL are on the new host, the other three are still on the theme default.

So two engine hosts in production is a migration state, not a quirk — but it is deliberate, and unpicking it ad hoc will break live PDPs.

New products use the new URL: customizer.vucustom.com/{env}/main.js.

Dev theme settings are not in git

jtb_custom_helmet_src and jtb_custom_helmet_environment are absent from sites/cascade-maverik/config/settings_schema.json and settings_data.json. Publishing a theme built from this repo blanks src and every helmet customizer dies. Pull the live theme JSON or copy both values out of Theme settings before shipping.

Why the override exists

VU asked us to move to the new engine URL. The override metafield was introduced so both engine versions could run side by side during the switch, one product at a time, instead of a single risky cutover.

Practical consequences: new products get the new URL; the three helmets still on the legacy bucket are unfinished migration, not a deliberate split; and the eventual tidy-up is to move them, flip jtb_custom_helmet_src to the new host, and drop the overrides. Coordinate that with VU rather than doing it opportunistically.

Independent overrides

Src and environment override separately, so a product can run a staging engine while reporting data-environment="production". Nothing warns you. Check both.

Cart thumbnails

The last line item property is treated as a recipe id:

https://silhouette3.jtbcustom.com/api/recipes/{recipeId}/images/thumbnail?{timestamp}

That host is VU's, not Shopify's — a 403 there is a vendor issue. The unused “Override VU Src Thumbnail” metafield was probably meant to swap this host per product for Z/SL on the newer engine, and was never wired into Liquid.

Differences and constraints vs Bauer

  • No error tracking

    Helmet load failures surface only as console noise and a broken UI. Bauer's vu_sentry.js approach ports over conceptually, though the shell differs.

  • Monolithic snippet

    3,226 lines holding markup, behaviour and config. Hard to test, easy to regress.

  • Engine migration is unfinished

    Z and SL are on VU's new URL; XRS Pro, XRS Youth and CPV-R are still on the legacy bucket. The end state is everything on customizer.vucustom.com, at which point the theme default can be flipped and the overrides removed. Sequence the remaining three with VU — do not cut them over unilaterally.

  • Theme setting IDs unpublished

    A repo publish can silently blank src. The most likely way to break Cascade.

  • Dead metafield

    “Override VU Src Thumbnail” is set on live products and read by nothing. Wire it or remove the definition.

  • Fonts from another shop's Files

    Register templates pull D-DIN from 1/0555/9838/3422, a client dev store. Same class of cross-store dependency as Bauer's icons, and site-wide rather than customizer-specific. See Dependencies.
