Dependencies

Every external service, integration, asset and account the customizers rely on, and who controls each one.

Ownership summary

No part of the running system depends on a developer account, a Nine15 account, or any other unmanaged resource. Every service in the inventory below is either a client-owned account or a public CDN.

Two things are worth knowing rather than acting on in a panic: some customizer icons are served from a client development store rather than production, and two Cascade theme settings exist only inside Shopify. Both are detailed below.

Nothing agency-held

There is no Nine15 server, proxy, build pipeline, API key or hosting in the request path. The theme is plain Liquid, CSS and JS in the client's Shopify. Every runtime call goes either to VU Custom, to the client's own accounts, or to a public CDN.

Hosted assets

Customizer chrome is hardcoded to Shopify Files on two client development stores. Both are client-controlled — 1/0555/9818/6772 is bauer-ca-dev and 1/0555/9838/3422 is a second client dev store — so nothing is lost at handover.

The consideration is that production storefronts, across every Bauer market, are reading from stores whose purpose is to be safe to break. All references sit in sites/_shared.

VU's public docs do not describe our integration

VU Custom's public embedding guide documents a loader-script pattern against silhouette.jtbcustom.com with a #jtbconfigurator div. Neither Bauer nor Cascade uses that. Both were built directly with VU against a different contract. Treat the gitbook as background on VU OS concepts, not as a description of what is deployed here.
