Troubleshooting

Symptom → cause → fix, both brands.

Triage first

DevTools → Network. Did main.js load from the VU host, and what status? Everything downstream depends on that answer, and it separates a settings bug from a vendor outage in about ten seconds.

Modal will not open

Clicking Customize does nothing

Causes, in order of likelihood

  1. Trigger attribute wrong. vu_main.js binds only [name="showmodal"]. The rich-text trigger block's Attribute field must be exactly that.
  2. Section not on the document. Trigger and section must be on the same page. A hero button on a landing page needs the section there too.
  3. Legacy block used. The vu_customizer block in main-product.liquid renders the snippet with no main_source, _product or variant — a dead shell. Use the VU Customizer section.

Confirm

document.querySelectorAll('[name="showmodal"]').length
document.getElementById('customizer')?.src

No trigger → cause 1. No #customizer or empty src → cause 2 or 3.

Loading state hangs, then the failure UI appears

Cause

Either main.js never loaded, or it loaded and the scene never rendered. vu_main.js gives up at 80s and shows the failed-loading UI.

Confirm

Network tab, filter main.js:

  • 404 — bad URL. Almost always vu_customizer_environment pointing at a folder that does not exist.
  • 403 — VU-side permissions.
  • 200 but no scene — the engine stalled on a GLB, texture or recipe fetch. Look for other failures on VU hosts.

Fix

404: correct the theme setting (production on live). Otherwise collect the failing URLs and escalate.

Sentry will already have VU main.js failed to load or VU scene render timeout (80s).

Broke immediately after a theme publish

Cascade — most likely cause

jtb_custom_helmet_src and jtb_custom_helmet_environment are not in the repo. A theme published from git has them blank, so src is empty and all five helmets die at once.

document.querySelector('#customizer').src   // empty → this is it

Fix: restore both values in Theme settings (search “JTB” / “custom helmet”), or roll back the theme. Detail.

Bauer

Check vu_customizer_environment and vu_customizer_country survived. Also note publishing flips Sentry from production-draft to production — alerts that were quiet during testing now fire for real.

Opens but renders wrong

Icons missing — restart, bag, chevrons, QR, Game Fit logo

Cause

Those assets are hardcoded to Shopify Files on client dev stores (1/0555/9818/6772 = bauer-ca-dev, and 1/0555/9838/3422). If a dev store is paused, archived, or its Files cleaned out, live PDPs lose them.

Confirm

Network tab, failed requests containing 0555/9818/6772 or 0555/9838/3422.

Fix

Re-upload to the production shop or theme assets and update the URLs. File list: Dependencies.

Raw translation missing: en.vu.vu-customizer.… on screen

Cause

Four keys are referenced by the snippet and absent from both CA locale files: load_fail, try_again, email_success, email_fail. The first two appear inside the load-failure UI, so the error message is itself broken.

Fix

Add all four under vu.vu-customizer in sites/bauer-ca/locales/en.default.json and fr.json.

Wrong delivery date

Resolution order — first match wins

  1. estimated_delivery metafield on the product. Should be blank on all live products; a stray value here is the most common cause.
  2. product.type == 'MyBauer-Steel' → blade lead time, else skate lead time. A mistyped product type sends it down the wrong branch.
  3. Custom-colour swap: only if the recipe's color_zones code is in the section's list. That list is empty on every live CA product, so this branch should be unreachable.
  4. Theme settings — live CA renders 22 / 36.

The date counts weekdays only, so it will not match a naïve today+N. That is correct.

Full logic.

A colour, size or option is missing

Not a theme issue

Option sets are VU-side configuration keyed on product slug and country.

Check before escalating

  • vu_customizer_country — VU derives pricing and option sets from it. A test change left un-reverted alters an entire market.
  • vu_customizer_environment — staging builds can carry different option sets.

Then send VU the slug, data variant, country and what is missing.

Cart

Add to cart fails after the shopper finishes

Priority

Highest — the design is complete and unpurchasable. Sentry tags it vu_error_type: add_to_cart and fires alert rule 17327463.

Cause

VU's cart library performs the POST, not the theme. On failure it emits customizer.add-to-cart-fail; we toast and capture.

Confirm

Network tab → /cart/add → read the response body. Common: variant out of stock or unpublished, wrong data-variant-id on the tag, or a VU-side cart failure.

Fix

Verify the variant is published and in stock first — that is the theme-fixable half. Otherwise escalate with the response body.

Cart line missing delivery date or SAP attributes

Cause

window.customizerLineAttributes is written on scene-rendered. If the scene never fully rendered, the array was never populated — but the shopper may still have added to cart.

Check

  1. Did the scene complete? A partially loaded customizer can still ATC without attributes.
  2. Are custom.product_category and custom.customization_type set? Those two attributes are conditional on the metafields existing.
  3. Has an underscore key been renamed? Spelling is an SAP contract.

Why it matters: the order succeeds and reaches manufacturing with missing data — worse than a visible failure, because nothing surfaces until production.

Cart thumbnails broken (Cascade)

Thumbnails come from silhouette3.jtbcustom.com — VU's recipe image API, not Shopify. A 403 or timeout is a vendor issue.

If it is only Z and SL: those are the two already migrated to VU's new engine URL, and the “Override VU Src Thumbnail” metafield that appears intended to repoint their thumbnail host was never wired into Liquid. Detail.

Sentry

Reading an alert

1 · environment

  • production — real shoppers, act.
  • production-draft — someone on a preview theme. Informational.
  • staging — dev shop. Ignore, and fix the rule that sent it.

2 · vu_error_type

  • add_to_cart — highest severity.
  • asset_load — check whether it is one data_variant or all of them.
  • scene_timeout — often a slow client; a burst means something real.

3 · scope

product, data_variant and region tell you single-product vs site-wide. Most of the response plan follows from that.

Sentry has gone silent

Causes

  1. defer or async added to the Sentry tags. The classic. Looks like a perf win, disables instrumentation entirely.
  2. CDN version bumped without updating SRI. Fails closed, silently.
  3. Ad blocker on your own browser. By design.

Confirm

VuSentry.enabled   // false with no blocker running = problem

Also legitimate

The new-issue rule can be correctly silent: issues group across environments, so anything first seen in production-draft is not “new” in production. Detail.

Too much noise in the project

Filter on vu_related:true rather than lowering sampleRate. If genuinely irrelevant errors are still arriving, extend ignoreErrors or denyUrls in vu_sentry.js — current lists.

Cascade only

Dev PDP appears to have no customizer

You fetched the password page. Use admin → View on Online Store, or the theme editor preview.

Z and SL behave differently from the other three

Expected. VU asked us to move to a new engine URL, and the override metafield lets both versions run in parallel during the switch. Z and SL are migrated; XRS Pro, XRS Youth and CPV-R are still on the legacy bucket.

So the split is a migration state, not a fault. Do not cut the remaining three over unilaterally — sequence it with VU — and never point any Cascade PDP at Bauer's host. Detail.

A helmet reports production but behaves like staging

override_vu_src and override_vu_environment are independent, so the engine URL and the environment label can disagree with nothing warning you. Check both — the URL is authoritative, the label is cosmetic.

document.querySelector('#customizer').src
document.querySelector('#customizer').dataset.environment

Vendor escalation

SymptomOwner
main.js 403VU — S3 permissions
main.js 404Theme — wrong environment setting
GLB / texture / recipe fetch failureVU
Missing option, colour or sizeVU — product configuration
Sudden CORS burst, no theme changeVU — has happened before (2026-07-24)
Cart thumbnail 403VU — recipe image API
Wrong lead time / dateTheme — settings or metafields
Missing icons, untranslated stringsTheme
Add-to-cart failureEither — check variant stock/publish state first

What to include

  • PDP URL, product slug, data_variant
  • Resolved #customizer[src] and data-environment
  • Country and locale
  • Failing request URLs with status codes
  • Onset time, and whether a theme was published near it

For Bauer most of this is already on the Sentry issue as tags. #bauer-vu-nine15 is shared with VU and is usually the fastest route.
