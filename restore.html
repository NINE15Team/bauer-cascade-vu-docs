The element API — and its one trap

setValue() fails silently

Passing an invalid code does not throw and does not warn. The element silently retains its previous value. You must read back and compare — there is no other way to know a write landed.

customizer.elements[code].setValue(vuCode)
// no error on a bad code — previous value silently retained
// read back element.value.code (or .name) and compare

Recipe read-back shape:

color.value              → { name: 'RED',     code: 'red' }
size_right.value (half)  → { name: '7 1/2',   code: '7_1-2' }
fit.value                → { name: 'FIT 3',   code: 'fit_3' }
tongue_personalization_name.value
                         → { name: 'LINDROS', code: 'LINDROS' }

Flow

  1. Wait for window.customizer.elements, or the first customizer.scene-rendered ({ once: true }).

  2. Render a debug banner of the current customizer.recipe — top-left, collapsible, resynced on customizer.recipe-updates-complete.

  3. Apply MOCK_SELECTIONS sequentially. Fired in parallel, recipe updates race and writes are lost.

  4. Per field: map key → element code → transform value → setValue → poll up to 1.5s. Personalization fields are debounced against the live render, so the write is not immediately observable.

  5. Toast + console: N/M applied, with VU's real rejection string for misses. Console prefix [VU restore selections].

Mock payload — Lindros, chosen because it is instantly visible on the tongue:

{
  color: 'red',
  sizeLeft: 7,
  sizeRight: 7.5,   // → "7_1-2", display "7 1/2"
  fit: 3,           // → "fit_3"
  tongue: 'classic_molded_felt_black',
  playerNumber: 88,
  playerName: 'LINDROS'
}

Skate-shaped map

Goalie steel and Fuse use different element codes. A miss against those products is a map gap, not a VU bug — do not raise it as one.

Running it

  1. On a dev theme only, uncomment in vu_customizer_snippet.liquid:

    <script src="{{ 'vu_customizer_restore_selections.js' | asset_url }}" defer="defer"></script>

  2. Open Supreme Shadow, or another skate whose options include red / fit 3 / that tongue. Wait for the scene.

  3. Expect the left recipe banner and a bottom-right toast.

  4. Re-comment before any production deploy. Left enabled it rewrites every shopper's skate to Lindros 88.

Check VU's native feature first

VU Custom's platform has Starting Points — a template previewed with customization pre-applied, used to drop a shopper into the customizer with selections already set. That overlaps directly with what this POC does by hand through setValue().

Before investing further here, confirm with VU whether Starting Points (or the recipe API behind ?recipe_id=) already covers the use case. Rebuilding a platform feature in theme JS would be the expensive way to get there.
