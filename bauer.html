Bauer

myBauer skate and steel customizer. Source: sites/bauer-ca + sites/_shared. Product templates and settings_data.json are Theme Editor–only.

Architecture

Host + shell. Liquid mounts the DOM and config; VU's S3 bundle owns 3D, GLB/textures, recipe state, variant mapping and POST /cart/add.js. Theme JS is chrome only: modal, tabs, focus trap, price, lead-time line attributes, ATC failure toast.

Cart ownership

The theme never calls /cart/add.js. It writes window.customizerLineAttributes on scene-rendered and VU's cart library reads that array. If line attributes are missing from an order, the usual cause is that the scene never fully rendered.

Boot sequence

  1. settings.vu_customizer_environment is interpolated into https://vu-customizer.s3.amazonaws.com/{env}/main.js. Shop-wide; there is no per-section engine override.

  2. Section settings supply product (VU slug) and data_variant. Neither is a Shopify handle. data_variant is downcased; product is not.

  3. customizer_values = { product, country } is declared with let in the snippet — deliberately not on window. vu_sentry.js reads it as a bare identifier. Moving it to window breaks region/product tagging.

  4. Sentry CDN bundles + vu_sentry.js run blocking; vu_main.js is deferred; an inline script injects the S3 bundle during parse. Why the order matters.

  5. #customizer carries data-environment, data-variant, data-variant-id, data-locale and the debug flags. Locale is en-us on CA English, fr-ca when request.locale.iso_code == 'fr'.

  6. On customizer.scene-rendered, lead time and SAP attributes are written to window.customizerLineAttributes.
